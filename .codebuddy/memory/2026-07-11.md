## 排查：PromptVault 侧边栏在 ChatGPT 上不显示

**现象**：侧边栏在 Pinterest 等普通网站正常，在 chatgpt.com 完全不出现（之前可以，近期失效）。

**根因（最终确认）**：manifest.json 的 `content_scripts.css` 声明了 `["sidebar.css"]`，Chrome 在 `document_end` 时自动将此文件作为 `<link>` 注入页面 `<head>`——这发生在任何 JS 执行之前，对 React SSR 页面直接触发 hydration mismatch (#418)。延迟注入、改挂载位置都无法绕过这个根因。

**修复方案**：
1. **manifest.json**：移除 `content_scripts.css` 中的 `"sidebar.css"`，Chrome 不再往主文档注入任何样式。
2. **sidebar.js**：CSS 全部走 Shadow Root 内部的 `injectSidebarStyles()`（fetch 兜底加载），TT policy 已有 try-catch。
3. host 挂在 `document.documentElement`（避开 React reconciler 范围）。
4. 创建时机用 `requestIdleCallback` + setTimeout 延迟（React SSR 站 1600ms）。

**修复**（仅改 `sidebar.js`，未引入新权限，不影响 Chrome 商店上传）：
- 整个侧边栏（toggle/overlay/panel/confirm dialog/toast）改为渲染在 **Shadow DOM**（host `#pv-sidebar-host` 挂在 body，内部 `attachShadow`）内，样式与逻辑完全隔离。
- CSS 通过 `injectSidebarStyles()` 注入 shadow root：优先同步复用 manifest 已注入到 document 的 `sidebar.css` 样式表，失败再 `fetch` 兜底。
- 新增 `_ttPolicy`（`trustedTypes.createPolicy('promptvault')`），`setHTML()` 包装所有 `innerHTML`，兼容 Trusted Types。
- 所有针对侧边栏 DOM 的查询改用 `sbEl/sbQ/sbQA`（指向 shadow root）。

**待跟进**：`command-palette.js` 用相同机制（`document.body.appendChild` + `innerHTML` + `document.head` 注入 style），在 ChatGPT 上大概率同样失效，尚未修复，等用户确认是否一并改。

## 策略调整 v2：Popup 插入 + Iframe 侧边栏双管齐下

### Popup 插入（已完成）
popup 三个卡片模板加了「插入」按钮（↓向下箭头图标），调用已有的 `insertPromptIntoPage()`。100% 兼容含 ChatGPT 在内的所有网站。

### Iframe 侧边栏（已完成，替代 Shadow DOM 方案）
用户确认执行 **A 方案（iframe 浮层）**，彻底解决 ChatGPT React hydration #418。

**架构**：
- **sidebar.js**（content script）：精简为 ~170 行，只负责创建 `<iframe>` + 监听 postMessage + 执行插入操作。不再有 Shadow DOM、Trusted Types、innerHTML 等可能被拦截的 API 调用。
- **sidebar-frame.html**（新）：独立扩展页面，包含完整侧边栏 HTML 结构 + 引用 sidebar.css / i18n.js / storage.js。
- **sidebar-frame.js**（新）：~580 行，包含全部侧边栏逻辑（状态管理、渲染、搜索/标签页/编辑/删除/置顶/拖拽排序/主题切换）。运行在扩展上下文（chrome-extension://），直接访问 chrome.storage。插入操作通过 `postMessage` 发给父页面。
- **manifest.json**：`web_accessible_resources` 新增 sidebar-frame.html/js/i18n.js/storage.js。
- **通信协议**：iframe→parent `{source:'promptvault-sidebar', type:'insert', text}`；parent 捕获后调用 UniversalInsert 或 fallback 直接操作输入框。

**关键优势**：
1. iframe 是独立浏览上下文，React/CSP/Trusted Types 完全不可见不可干预
2. 所有网站统一走 iframe 路径，无需区分站点类型
3. 页面主文档零 DOM 变动（只有一个 `<iframe>` 标签被 append 到 `<html>`）
4. popup 插入作为补充方案保留

**图标改动**：popup 的「插入」按钮从 ↘ 左下箭头改为 ↓ 向下箭头（更符合输入框在弹窗下方的直觉）。

## 策略调整 v3：ChatGPT 彻底零注入 + 修复模板 HTML 坏损

### ChatGPT 零注入策略（已实施）
用户确认执行"放弃 ChatGPT 注入式 UI"。最终方案：
- **sidebar.js**（content script）：`init()` 顶部检测 `REACT_SSR_HOSTS`，匹配则直接 `return`——不创建 iframe、不追加任何节点、不监听消息。ChatGPT/Claude 完全零 DOM 操作。
- **command-palette.js**：同样在 IIFE 顶部检测 React SSR 站点 hostname，匹配则直接 return。
- **效果**：ChatGPT 上 #418 hydration 错误彻底消除、无闪烁、console 干净。用户体验完全依赖 popup 插入按钮。

### 修复 popup.js 模板 HTML 坏损（关键 bug）
**根因**：三个卡片模板（常规/分组/置顶）中，编辑/复制按钮的 `<button class="prompt-card-action edit/copy">` **开始标签丢失**，导致：
1. 编辑/复制图标裸露在 DOM 中（不在 button 内），不可点击
2. 多余的 `</button>` 闭合标签破坏后续按钮结构
3. 插入按钮事件绑定受影响 → 用户反馈"点插入没用"
**修复**：三个模板全部补回缺失的 `<button>` 标签和正确的 class/data-id 属性。

### 附带修复
- 清除常规列表渲染函数中的重复 `.insert` 事件绑定（同一选择器绑了两次 click）
- CSS 图标对齐优化：`.prompt-card-action` 改为固定 28×28px 尺寸 + inline-flex + svg display:block
